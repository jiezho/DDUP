# 个人上下文智能工作台：MVP 需求追溯矩阵

> 版本：V1.3
> 日期：2026-08-26
> 状态：已完成（S1-04）  
> 基线：已确认的 `MVP范围与验收标准.md`、需求分析 V1.2、UI/功能 Spec V1.1

## 0. 目的

本矩阵把 MVP 验收场景追踪到产品功能、页面、领域对象、API、测试和实施任务。后续改变任意一列时，应检查同一行的其他交付物，避免“需求、原型、接口和测试各自正确但彼此不一致”。

状态含义：

- `基线已有`：现有 `person_dashboard` 已有可复用实现；
- `原型已有`：高保真原型已表现，尚无真实后端；
- `待实现`：MVP 工程任务；
- `P1`：不阻塞首个垂直切片，但接口/模型需要预留。

## 5. 测试资产规划

| 测试层 | 重点 | MVP 最低要求 |
|---|---|---|
| 单元测试 | 状态机、校验、权限、ID/版本、排序与转换 | 每个领域命令有正常和拒绝用例 |
| Repository/迁移 | 事务、约束、升级、备份恢复 | 每个迁移可从空库执行并有回滚/恢复说明 |
| API 契约 | Schema、错误码、幂等、分页、权限范围 | 机器校验请求/响应和错误结构 |
| 集成测试 | 文件+数据库+索引+审计一致性 | 捕获、项目、搜索、审批、恢复链路 |
| AI/检索评测 | 召回、引用、无答案、越权、提示注入 | 固定脱敏测试集和可重复评分 |
| E2E | 浏览器真实流程和移动断点 | MVP-AC-01–15 至少各有一条端到端证据 |
| 发布验证 | 构建、隐私、备份、回滚 | 发布清单全部有结果或批准的降级 |

## 6. 变更控制

- 新增或删除 P0 功能时，先更新 `MVP范围与验收标准.md`，再更新本矩阵；
- 数据对象/字段改变时，同步检查 API、权限、迁移、备份和引用；
- 页面改变不等于业务需求改变；若只是视觉/布局调整，只更新页面和 E2E 列；
- Runtime 或连接器改变不能绕过统一对象、权限、审批和审计；
- 任何一行没有测试证据时，不得把对应验收项标记为已通过。
