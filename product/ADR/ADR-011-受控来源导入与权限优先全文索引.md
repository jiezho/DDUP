# ADR-011：受控来源导入与权限优先全文索引

> 状态：已接受  
> 决策日期：2026-08-25  
> 对应阶段：G4 后 S4-01、S4-02  
> 继承：ADR-002、ADR-003、ADR-008、ADR-010

## 背景

S4 需要把文件来源变为可验证的数据对象，并建立跨 Project、Task、Capture、Document 的统一发现能力。直接读取任意客户端路径会扩大本地文件暴露面；把派生正文或搜索索引当作业务真源会造成来源漂移；在权限过滤前召回正文则存在越权泄漏风险。

## 决定

- 首个导入切片只接受 API 正文中的虚构 Markdown，拒绝客户端路径、未知扩展名、空解析结果和超限请求。
- 原始字节使用 SHA-256 内容寻址保存在受控来源目录；SQLite 保存 Source、不可变 SourceVersion、Document、审计与 Outbox 元数据。
- 业务事务失败时补偿删除本次新建且未被引用的 blob；重复内容和重复幂等请求不产生额外文件或版本。
- FTS5 trigram 索引是可从业务真源重建的派生数据，统一索引 Project、Task、Capture、Document。
- 查询先确认会话与空间，再应用项目、对象类型和日期范围；未知空间和不匹配项目按不披露原则返回。
- Document 结果固定到 `source_version_id + char_range`；业务对象只返回对象 locator，不冒充可引用原文。
- 混合/向量召回、重排和回答服务不包含在本 ADR；须由 G5a 设计和 G5b 评测另行决定。

## 后果

首版获得可离线、低运维、可追踪且权限优先的全文基线，并能把模型或向量方案与稳定对照组比较。代价是目前只支持 Markdown，字符定位还不是完整的段落/页码引用，短查询需要受控 LIKE 回退，语义改写召回能力有限。

## 回退与复核

`context_search` 可删除后从 Project、Task、Capture、Document 重建，不影响业务真源。受控 blob 只能通过引用计数和审计过的清理流程删除。若后续混合检索未在固定评测集上证明收益，则保留本 ADR 的全文方案为默认实现。
