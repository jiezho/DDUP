# ADR-001：Node 24、React/Vite 与独立本地服务

> 状态：已接受  
> 决策日期：2026-08-24  
> 对应 G2：A1、A2、A3、A4、A11、A13

## 背景

现有高保真原型已经使用 React 19、Vite 6 和 ESM JavaScript，服务能力则集中在体积较大的 Vite 插件中。项目需要可独立测试、可本地部署的业务服务，但首个 MVP 不值得承担框架重写、全量 TypeScript 迁移或 monorepo 改造。

## 决定

- Node 24 LTS 为唯一开发、CI 和运行基线，最低 24.15；大版本保持一致。
- 保留 React 19 + Vite 6，以路由和功能切片渐进迁移原型。
- 将业务 API 从 Vite 插件抽成独立 Node 服务，HTTP 适配层使用 Fastify 当前受支持主版本。
- MVP 继续使用 ESM JavaScript、Zod 和 JSDoc，不做全量 TypeScript 迁移。
- 保持单一 `Workbench` npm 包；按领域、仓储、搜索、运行时和 HTTP 分层。
- 本地 Node 服务只监听回环地址，并在生产模式提供静态前端与 API；PWA 是移动基础入口。

## 后果

好处是复用现有 UI、缩小迁移面，并让领域逻辑脱离 Vite/Fastify。代价是短期存在旧插件与新服务并行，且 Fastify 成为新的生产依赖，需要版本锁定与依赖审查。

## 回退与复核

HTTP 层不得进入领域对象。若 Fastify 的维护、安全或体积不符合要求，可替换为 `node:http` 适配器。若未来出现多人协作、远程部署或桌面封装需求，另立 ADR，不通过简单开放监听地址实现。
