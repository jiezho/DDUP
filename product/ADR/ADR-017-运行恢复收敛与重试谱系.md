# ADR-017：运行恢复收敛、检查点与重试谱系

> 状态：已接受
> 日期：2026-09-01
> 关联：ADR-004、ADR-005、ADR-015、ADR-016；S5-03

## 背景

运行历史只有事件回放时，进程中断后的 `running` 状态会长期悬挂；如果直接覆盖原 Run 或自动重放工具，又可能重复产生业务副作用。正式运行中心还需要在浏览器断线后恢复事件，而不能把连接状态当成运行真源。

## 决定

1. Workbench 持久化可验证 Checkpoint，只保存 Run 版本、状态、事件序号、上下文摘要、已完成 ToolCall ID 和 Candidate ID；不保存密钥、Prompt 正文或长期记忆。
2. 服务启动时把遗留 `queued/running` Run 原子收敛为 `failed + RUNTIME_RECOVERY_REQUIRED`，追加安全失败事件、Checkpoint、Audit 和 Outbox；不伪装为成功，也不自动恢复 Runtime 私有状态。
3. 安全重试永远创建新 Run，并通过 `retry_of_run_id` 保留谱系。仅当原 Run 明确标记 retryable、没有执行 ToolCall、固定 ContextPackage 仍有效且版本一致时开放；其他情况要求用户重新提供或确认输入。
4. SSE 只是持久化 RunEvent 的投递投影。`Last-Event-ID`/`after_seq` 从已处理序号后恢复，允许重复投递；断开连接不取消 Run，终止必须调用取消命令。
5. 正式 UI 只显示真实 Run、事件、Checkpoint、Candidate 和 Approval；批准与应用仍保持两个独立动作。

## 结果

- 崩溃恢复不会产生无主运行或重复工具副作用；
- 原始失败记录不可变，重试结果可以独立审计和比较；
- 浏览器刷新、移动端切换和 SSE 重连不丢失持久化进度；
- 当前 `native-v1` 仍不支持 Runtime 私有 resume、steer、模型回答或外部动作，`resume=false` 保持不变。

## 退出与演进

未来 Runtime 若提供可验证的 opaque checkpoint，可在新的 ADR 中增加显式 resume；仍必须创建恢复记录、重新校验 ContextPackage/Policy/Tool 预算，并证明重复恢复不会重复副作用。

## 证据

- migration 010：`run_checkpoints` 与 `agent_runs.retry_of_run_id`；
- JSON 回放、SSE `Last-Event-ID`、取消、异常重启、安全重试和跨重启测试；
- AI 运行中心桌面/390px Playwright 完整闭环截图；
- OpenAPI 1.10.0。
