# ADR-005：Agent Runtime 与 Tool Gateway 松耦合

> 状态：已接受  
> 决策日期：2026-08-24  
> 对应 G2：架构目标、运行模式；延续运行时融合方案

## 背景

DeepSeek Harness 和 Hermes 都能执行多步 Agent 任务，但版本、工具、记忆和运行模型会变化。业务数据、审批和长期知识若交给某一运行时，将造成锁定、双真源与权限失控。

## 决定

- Workbench 持有项目、知识、权限、审批、审计和运行记录的业务真源。
- 所有执行引擎通过稳定 `AgentRuntime` 适配器接入。
- 所有业务读取和写入只经过 Workbench Tool Gateway。
- 一个 Run 只能有一个主 Runtime；禁止 Harness/Hermes 双主循环或互相嵌套。
- 运行时内部记忆和日志只能产生待确认候选，不能直接成为长期知识。
- Native Mock/基础适配器先实现；Harness 保持隔离只读 POC，Hermes 保持可选运行时/消息网关候选。

## 后果

业务可以替换运行时并统一审批、事件和审计，代价是需要协议映射、能力协商和适配器契约测试。松耦合不等于已集成；没有代码、测试和运行证据时，界面必须标为候选或 POC。

## 回退与复核

任一外部运行时可整体停用并退回 Native 路径。运行时切换必须创建新 Run 和最小上下文包，不能继续复用另一个运行时的私有会话状态。
