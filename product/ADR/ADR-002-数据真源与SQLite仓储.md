# ADR-002：文件与 SQLite 的数据真源划分

> 状态：已接受  
> 决策日期：2026-08-24  
> 对应 G2：A5、A6

## 背景

项目既要保留论文、网页、Markdown 和附件等开放内容，又要支持项目、任务、讨论、审批和审计的关系、事务与并发控制。把同一对象同时写入文件和数据库会形成双真源。

## 决定

- 原始资料与附件以受控文件目录为权威真源。
- 项目、任务、讨论、决策、知识条目、审批和审计等结构化对象以 SQLite 为权威真源。
- 使用 Node 24 内置 `node:sqlite`，所有访问经过 Repository 端口。
- 全文索引、向量和图谱布局均为可重建派生数据。
- JSON/Markdown 仅作为导出快照，不参与实时双写。
- 迁移前完成 Windows/Linux、事务、WAL、备份恢复、FTS5 与性能可靠性 Spike。

## 后果

这提供单机事务能力和开放内容可移植性，但导入文件需要暂存状态、哈希和修复流程来维持文件与元数据一致。`node:sqlite` 仍需通过可靠性验证，不能仅凭 Smoke Test 宣称生产可用。

## 回退与复核

Repository 契约保持稳定。若 Node LTS 的 SQLite API 不兼容、备份恢复不可靠或并发阻塞不可接受，后端可替换为锁定版本的 `better-sqlite3`；不改变领域模型和 HTTP 契约。
