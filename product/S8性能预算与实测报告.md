# S8 性能预算与实测报告

> 版本：V1.1
> 日期：2026-09-15
> 状态：本地轻量模式与前端 JavaScript 包体预算通过；分发包、浏览器时延、长时间运行和混合检索预算未完成

## 1. 预算

| 指标 | 首轮门槛 |
|---|---:|
| 服务和迁移就绪 | ≤ 5,000 ms |
| 健康检查 p95 | ≤ 100 ms |
| 项目列表 p95 | ≤ 300 ms |
| FTS 检索 p95 | ≤ 500 ms |
| 普通项目写入 p95 | ≤ 500 ms |
| 默认进程 RSS | ≤ 1,024 MiB |
| 浏览器入口 JavaScript（未压缩） | ≤ 300 kB |
| 任一 JavaScript 分块（未压缩） | ≤ 500 kB |

该预算用于本地优先的默认轻量模式。BGE-M3 sidecar、OCR、音频和外部模型使用独立预算，不能用本结果描述为生产可用。

## 2. 可复现方法

- 命令：`npm run bench:release`
- Runtime：Node v24.19.0，Windows x64。
- 全部数据为运行时创建并删除的虚构数据。
- 数据量：230 个项目、100 篇 Markdown 文档。
- 健康检查、项目列表和 FTS 各测量 100 次；项目创建测量 30 次。
- 使用 Fastify 本地注入衡量服务处理时间，不包含浏览器网络、磁盘冷启动和分发包启动器开销。

## 4. 2026-09-15 前端包体实测

- 所有正式页面、原型、全局搜索和文档阅读器均改为按需加载；页面切换使用带 `role=status` 与 `aria-live=polite` 的加载状态。
- 构建加入 `verify-client-bundle-budget.mjs` 硬门，后续入口或任一 JavaScript 分块超限会直接让生产构建失败。
- 入口脚本从原约 1.55 MB 降至 258.81 kB（gzip 82.76 kB）；最大异步分块为抖音页面 464.77 kB（gzip 126.50 kB）；共 67 个 JavaScript 分块，构建不再出现 500 kB 大块告警。
- 上述数值来自 Node v24.19.0、Vite 6.4.3 的本地生产构建；它是静态产物体积，不等同于真实设备的首屏可交互时间。

## 5. 尚未关闭的预算项

- 浏览器冷启动、首屏可交互和弱网条件尚未进入同一份自动预算。
- 10 万对象/100 万关系门已有 SQLite CI 证据，但尚未在真实业务 Schema 上测量 UI/API p95。
- 中文字体资源仍较大，真实浏览器字形请求、缓存命中和弱网体验需要单独测量后再决定是否裁剪。
- 分发包首次启动、跨设备恢复、连续七天内存趋势尚未测量。
- 本结果不能代表真实私有数据、外部连接器或模型调用成本。
