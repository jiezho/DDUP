## 2. 运行时影响分析

### 2.1 FlagEmbedding 候选

PyPI 元数据列出的主要依赖包括 PyTorch、Transformers、Datasets、Accelerate、Sentence Transformers、PEFT、SentencePiece、protobuf 和 ir-datasets。优势是与 BGE 官方用法一致、适配工作量低；风险是传递依赖多、磁盘与漏洞面较大，且 1.4.2 在本审查前一天发布，尚缺本项目兼容性证据。

因此不把它加入 Workbench 的 `package.json`，也不视为生产依赖。确认后先在仓库外隔离目录解析 CPU 依赖树、许可证和精确下载量；发现 GPU/CUDA、编译器或非必要训练组件被强制引入时停止并改评更小的推理适配器。

### 2.2 llama.cpp 替代路径

官方 server 支持 embedding 与 rerank 接口，Windows 默认回环监听，适合形成进程级 Adapter。其优势是单独进程、回环 API 与可替换性；不足是 BGE-M3 需要经过 GGUF 转换或取得可复现兼容权重，当前尚无本项目验证证据。首轮不采用；若 Python 依赖闭包不可接受，再单独审查固定构建与模型转换链。内置工具或 MCP 能力保持关闭。

### 2.3 安全与卸载

- 模型和索引只处理全合成资料；
- 运行服务只绑定 `127.0.0.1`，使用随机端口或受控固定端口；
- Runtime 只通过 Embedding/Rerank Adapter 输入输出向量或分数，不直接访问业务数据库；
- 模型、缓存、虚拟环境和派生索引可整体删除；SQLite 业务真源和 FTS 回退不变；
- 不执行模型仓库自定义代码，不启用 SQLite 扩展，不开启 llama.cpp tools/MCP；
- 每次 POC 记录 Node/Python/OS、模型完整 revision、哈希、峰值内存、索引耗时、p95 与评测指标。
