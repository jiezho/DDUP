> 版本：V1.6  
> 日期：2026-08-24  
> 状态：已完成（S0-03/S0-04）  
> 审计范围：`person_dashboard-main/Workbench/`、虚构示例 Vault、现有测试和高保真原型

## 0. 结论

工程起点不是空壳，已经具备可复用的本地 Vault 读取、Markdown 解析、全文搜索、知识图谱、阅读器、笔记、实时索引、受控写入、安全路径校验和较完整测试资产。G3 后又完成了本地安全服务与 Project→DailyReview 的 SQLite 垂直切片；但 Source/Knowledge/Context、AI 治理和生产运维仍未形成完整平台。

建议：

1. 保留索引、阅读、图谱、安全、同步和测试资产；
2. 不直接在现有大型 Vite 中间件中继续堆叠项目、权限、AI 和连接器；
3. 先冻结领域模型与 API，再把现有能力逐步封装为独立服务/模块；
4. 高保真 `/prototype` 继续作为产品验收参考，不直接视作生产页面；
5. 已完成的第一条工程垂直切片继续作为统一项目对象和本地持久化底座；Runtime 保持未接入状态，待 S5 通过独立契约实现。

## 4. 主要工程缺口

### 4.1 阻塞正式 MVP 的缺口

1. **没有统一项目领域模型。** 项目、任务、讨论、决策和里程碑目前仅存在于原型概念中。
2. **没有空间与 ACL。** 本地回环和路径白名单不能替代对象级、空间级和模型级权限。
3. **没有正式持久化与迁移。** 新对象需要 ID、版本、关系、软删除、审计和升级策略。
4. **没有生产服务边界。** 当前 `/api/*` 位于 Vite 插件内，适合本地开发，不适合作为长期业务服务容器。
5. **没有统一上下文目录。** 现有索引面向文件和特定页面，不能表达所有项目/模块对象与权限。
6. **没有引用问答契约。** 需要来源片段、定位、检索范围、推断标识和无依据拒答。
7. **没有 Runtime Gateway。** 原项目 runner 不等同于已设计的可替换 Agent Runtime、工具网关和审批桥。
8. **没有正式身份、密钥、备份和恢复方案。** 这些必须在真实数据接入前完成。

### 4.2 结构与维护风险

- `server/vault-index.mjs` 约 98 KB，聚合多种解析和垂直业务逻辑；
- `server/vite-plugin-workbench.mjs` 约 60 KB，集中大量 API 路由和服务组装；
- `src/prototype/PrototypeApp.jsx` 是高保真概念入口，应按领域拆分而不是继续膨胀；
- 正式基线页面与目标原型并存，导航、路由和样式有两套表达；
- API fallback 对演示友好，但生产环境必须区分“无数据”和“服务不可用”；
- 本地、托管两种构建能力不同，需要在 UI 和部署文档中明确能力矩阵；
- 根目录许可证与 Workbench README 仍提示许可证未最终确认，外部分发前必须解决。

### 4.3 UI 与性能债

- 生产主 JavaScript：约 1,541.25 kB，gzip 约 465.64 kB；
- CSS：约 347.60 kB，gzip 约 64.60 kB；
- 构建仍提示单 chunk 超过 500 kB，需按路由拆包并延迟加载图表、编辑器和原型；
- 已有评审指出正式字号、Dialog 焦点圈定、键盘顺序和移动状态需要补齐；
- 字体文件体积较大，需要按字体族/字重和加载策略评估。

## 7. 进入架构设计前的建议

### 7.1 必须保持

- 默认回环访问和真实路径脱敏；
- 演示数据必须明确为虚构；
- 缺失数据不虚构；
- 写入先确认、独占创建、可审计；
- realpath + allowlist + symlink 逃逸防御；
- 索引失败保留最后可用版本并暴露 degraded 状态；
- Markdown/JSON 作为可移植真源，派生索引可重建。

### 7.2 架构设计需要回答

1. 项目对象和知识文件是否共用一种存储，或采用“结构化数据库 + 开放文件真源”组合；
2. 单机服务如何从 Vite 插件迁移到可测试、可部署的正式服务；
3. 身份、空间和对象 ACL 在单用户 MVP 中如何保持简单但可演进；
4. 全文、向量、图谱索引如何共享统一 Source/Object ID；
5. 本地与托管模式分别允许哪些数据和工具能力；
6. Runtime Gateway、Tool Gateway、Approval 和 Audit 如何形成稳定契约；
7. 备份、恢复、删除和 Schema 迁移如何验证。

G2/G3 已于 2026-08-24 按推荐项确认。此处记录当时基线；截至 2026-08-28，正式项目持久化、权限前置检索、`native-v1` Runtime Adapter 与 Task Candidate Tool/Approval 首版已经实现，Harness/Hermes 仍保持未连接候选状态。
