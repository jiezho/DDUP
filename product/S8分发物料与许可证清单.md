# S8 分发物料与许可证清单

> 版本：V0.2
> 日期：2026-09-16
> 状态：生产锁依赖与构建物哈希清单已建立；许可证和实际跨设备分发边界仍需人工确认，不构成发布批准

## 1. 范围与复现

- 执行 `npm run release:inventory`，输出 `dist/release/dependency-inventory.json`。
- 清单固定根包名称/版本、lockfile SHA-256，以及每个未标记 `dev` 的锁条目名称、版本、许可证声明、直接/可选/已安装状态、来源和完整性字段。
- 清单不写入绝对路径、账号、凭据、业务数据或 Vault 正文。
- 该清单按 `package-lock.json` 的生产标记统计，不是对最终浏览器/服务端构件的可达性分析，也不是 SPDX/CycloneDX SBOM 或法律意见。

## 3. 阻断与下一步

生产构建现在自动生成 `dist/release/artifact-manifest.json`，固定 `client/`、`server/`、`.openai/` 和依赖清单的完整文件集合、逐文件 SHA-256、总字节数与聚合 SHA-256。2026-09-16 本地构建结果为 131 个文件、18,258,965 字节，聚合 SHA-256 为 `d44f987465ba9df2b005c3058511061d3b28d104e6d6da0d784a6bd2e57264b4`。校验器会拒绝修改、缺失、额外文件、重复路径、路径逃逸和摘要不一致。

## 4. 仍需关闭的边界

1. 版权所有者尚未为项目代码选择并确认发布许可证；此前 A15 边界继续有效，只允许本地开发、研究和内部合成演示。
2. GSAP 的专用许可证需要按计划分发方式人工复核，不能按 MIT 等常见 SPDX 许可证自动放行。
3. 49 个 esbuild、Rollup 和 fsevents 平台可选条目需在目标 Windows/Linux 构建环境补齐许可证原文与 notices；当前清单只记录缺口。
4. 最终分发包形成后，还需做构件可达性分析、第三方 notices 和跨设备恢复演练；开发依赖与 Playwright 浏览器不应进入产品分发包。

结论：机器清单解决了“锁定了什么、哪些元数据缺失”的可复现问题，但许可证门仍未关闭，G8 不应据此批准对外发布。
