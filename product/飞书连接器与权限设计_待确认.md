# 飞书连接器与权限设计

> 版本：V1.0
> 日期：2026-09-14
> 状态：待确认（G7a/G7b）
> 边界：本文件只完成设计冻结；未创建真实飞书应用、未申请权限、未写入凭据、未发送消息。

## 1. 需要确认的决定

| 编号 | 推荐默认项 | 替代方案 | 不确认的影响 |
|---|---|---|---|
| G7a-1 | 飞书是可替换入口，Workbench 继续持有项目、任务、知识、权限与审计真源 | 在连接器内保存业务状态 | 无法开始连接器数据模型和契约开发 |
| G7a-2 | 使用“租户 + 飞书用户标识 → Principal → Space 角色”显式绑定；未知身份失败关闭 | 自动创建本地身份 | 无法验证身份隔离和撤销 |
| G7a-3 | 分阶段申请最小权限：先身份/接收/卡片回调，最后才申请按目标发送 | 一次申请宽权限 | 不接真实平台，不影响合成适配器 |
| G7a-4 | 所有入站事件先验签、校时、去重，再进入 Tool Gateway | 卡片处理器直接写业务 API | 无法达到重复投递与重放安全门 |
| G7a-5 | 捕获创建 L1 候选；任务变更复用现有本地权限；外部发送为 L3，每次绑定目标与内容摘要审批 | 机器人自动写入/自动发送 | 外部写入保持关闭 |
| G7a-6 | 凭据只进入系统凭据存储或进程环境，不进入 SQLite、日志、仓库和备份 | 加密后写入业务数据库 | 真实授权保持阻塞 |
| G7a-7 | 撤销先禁用账号和计划任务，再删除令牌；保留脱敏不可变审计 | 解绑时删除业务数据或审计 | 无法实现安全解绑 |
| G7a-8 | 第一版只做单聊捕获、带引用问答、今日任务卡片；群聊和小程序后置 | 首版同时覆盖群聊/小程序 | 首版范围无法冻结 |
| G7b-1 | 所有主动通知默认关闭，用户逐项选择项目、类型、目标、频率和静默时段 | 安装后默认开启 | 通知开发只保留禁用状态 |
| G7b-2 | 每日同目标限频、同类合并；失败有限重试后停止 | 无限重试或按事件即时轰炸 | 无法通过通知安全门 |
| G7b-3 | 日报/周报只生成待确认草稿，明确批准后才外发 | 自动生成并自动发送 | 定时简报保持关闭 |

推荐：G7a-1～8、G7b-1～3 全部采用推荐项。

## 2. 架构边界

```text
飞书事件/卡片
  → Connector Inbox（验签、校时、去重、身份解析）
  → Workbench Tool Gateway（权限、审批、幂等、审计）
  → 业务真源
  → Connector Outbox（目标绑定、限频、有限重试、结果审计）
  → 飞书
```

- 连接器不得直接访问 Workbench 数据库。
- Runtime 不得持有飞书长期凭据，也不得绕过 Tool Gateway。
- 飞书会话状态不是长期知识；只能产生 Capture、Candidate 或显式业务动作。
- Hermes 当前保持 `connected=false`，不作为本设计的默认实现。

## 3. 首版数据对象

| 对象 | 关键字段 | 规则 |
|---|---|---|
| ConnectorAccount | provider、tenant_digest、status、revoked_at | 不保存明文凭据 |
| IdentityLink | account_id、external_user_digest、principal_id、space_id、status | 一个映射必须显式批准 |
| InboundEvent | provider_event_id、received_at、payload_digest、state | 唯一键保证重复投递不重复写入 |
| DeliveryAttempt | approval_id、target_digest、content_digest、attempt、state | 只保存必要摘要和投递状态 |
| NotificationRule | principal_id、space_id、scope、quiet_hours、daily_limit、enabled | 默认 `enabled=false` |
| ConnectorRevocation | account_id、actor、reason_code、occurred_at | 不可变审计，不含令牌 |

## 4. 安全处理顺序

1. 验证事件签名、时间窗口和事件格式；失败不解析正文。
2. 以租户、应用和事件 ID 形成去重键。
3. 解析显式身份映射；未知、停用或已撤销身份统一拒绝。
4. 构建最小 Workbench 请求，不把平台权限等同于 Space 权限。
5. 写操作执行权限、审批、幂等和审计检查。
6. 外发前复核批准时的目标摘要与内容摘要；发生变化必须重新批准。
7. 投递结果进入 Outbox 审计；达到重试上限后停止。

## 5. 首版卡片契约

### 快速捕获

- 只接受短文本和 HTTPS 链接；不自动抓取链接正文。
- 创建 Capture 或候选知识，不直接晋升长期知识。
- 卡片回显对象 ID、项目和当前状态，支持安全撤销。

### 带引用问答

- 复用 ContextPackage、AnswerAttempt、Claim 和 Citation 真源。
- 无证据、证据漂移、不可信指令或越权时明确拒答。
- 卡片只展示最小引用摘要，打开原文仍回到本地 Workbench。

### 今日任务

- 只允许查看、完成和延期本人有权操作的 Task。
- 版本冲突显示“状态已变化”，不覆盖 PC 端新状态。
- 重放相同卡片动作返回原结果，不重复写入。

## 6. 撤销和故障策略

- 撤销顺序：禁用账号 → 停止规则和 Outbox → 删除/失效令牌 → 写入审计。
- 飞书不可用时不影响本地 Workbench；待发送项保持失败状态并可人工重试。
- 连接器升级失败时回退适配器，不回滚业务数据库。
- 未通过 G7 的实现只能使用虚构身份、虚构消息和本地 Fake Connector。

## 7. 验收矩阵

- 未绑定身份不能读取任何业务对象。
- 跨 Space 请求不泄漏对象是否存在。
- 同一事件重复投递十次只产生一次业务写入。
- 过期签名、重放回调和篡改卡片均不写入。
- 撤销后新事件和后台投递全部拒绝。
- PC 与飞书操作收敛到同一对象版本和审计链。
- 外发目标或内容在审批后变化时必须重新审批。
- 通知默认关闭，静默时段和每日上限可验证。

## 8. G7 后实施顺序

1. 先实现 Fake Connector、数据迁移、Inbox/Outbox 和契约测试。
2. 通过合成身份、重复投递、撤销和失败恢复测试。
3. 再由用户创建真实飞书应用并授权当前官方最小权限。
4. 最后联调真实单聊和卡片；通知仍等待 G7b。
