# 旧版 XLSX 导入依赖处置

> 版本：V0.1  
> 日期：2026-08-24  
> 状态：待确认  
> 触发原因：G3 后依赖审计发现原项目 `xlsx@0.18.5` 存在已公开的高风险安全告警，而 npm 注册表没有可直接升级的修复版本  
> 影响范围：仅现有 Vault 中旧版 XLSX 明细读取；不涉及新项目数据库、上传接口或真实资料接入

## 0. 需要确认的决定

| 编号 | 推荐默认项 | 替代方案 | 不确认的影响 |
|---|---|---|---|
| X1 | 从 SheetJS 官方 CDN 获取并在仓库内固定 `xlsx-0.20.3.tgz`，以本地 `file:` 依赖安装 | 移除/禁用旧版 XLSX 读取；或暂留 0.18.5 | 不能解除当前生产依赖高风险告警，发布门保持阻塞 |
| X2 | 下载后记录来源 URL、SHA-256、许可证和包内文件清单；验证无安装脚本后才提交 | 仅依赖远程 URL，每次安装联网获取 | 供应链证据不足，无法稳定复现构建 |
| X3 | 旧版解析仅允许读取受控 Vault 路径，单文件上限 20 MiB，并限制工作表、行和单元格规模 | 只做文件大小限制 | 恶意或异常文件仍可能造成资源耗尽 |
| X4 | MVP 不新增 XLSX 上传/API；只用明确标记的虚构 fixture 做正常、异常和超限测试 | 立即扩展上传能力 | 扩大攻击面，且超出当前垂直切片 |
| X5 | 若许可证、完整性、Node 24 兼容或安全测试任一失败，回退为禁用旧版 XLSX 读取并删除依赖 | 保留旧依赖并接受风险 | 高风险依赖会继续阻塞发布 |

推荐确认语句：`XLSX处置全部按推荐项确认。`

## 1. 现状与事实

- `xlsx` 是 G3 前已存在的直接生产依赖，当前版本为 `0.18.5`；不是本轮新增。
- 代码只在 `server/vault-index.mjs` 中用于读取旧版 `.xlsx` 明细，并标记来源为 `official-xlsx-legacy`。
- 当前 `npm audit` 剩余 1 个 high 级依赖问题，涉及原型污染和正则表达式拒绝服务；公告给出的修复版本分别为 `0.19.3` 和 `0.20.2`。
- npm 注册表中的 `xlsx` 仍停留在 `0.18.5`，因此 `npm audit fix` 无法修复。
- SheetJS 官方安装文档说明 npm 注册表副本已过时，当前官方发布渠道是其 CDN，并给出 `0.20.3` tarball；官方还建议为稳定构建保存本地副本。

这不表示 `0.20.3` 已在本项目中验证或安装。下载、校验和替换必须在本确认通过后执行。

## 2. 推荐方案

### 2.1 固定和验证供应链

确认后执行以下受控流程：

1. 仅从 `https://cdn.sheetjs.com/xlsx-0.20.3/xlsx-0.20.3.tgz` 下载；
2. 将 tarball 保存到 Workbench 的 `vendor/`，不执行其中代码；
3. 记录 SHA-256、文件大小、许可证、package metadata、包内文件清单和安装脚本检查结果；
4. `package.json` 使用精确本地 `file:vendor/xlsx-0.20.3.tgz`，lock 不引用浮动版本；
5. 重新执行完整测试、构建、隐私扫描和生产依赖审计；
6. 审计必须不再出现该两项告警，否则回退并禁用功能。

本地 vendoring 仅固定一个已经批准的第三方制品，不授权二次分发。项目许可证和第三方 notices 未完成前仍保持内部本地开发状态。

### 2.2 解析边界

即使依赖升级，XLSX 仍按不可信输入处理：

- 入口限定为既有 Vault 受控目录，经 `realpath + allowlist` 校验；
- 单文件最大 20 MiB；
- 默认最多 32 个工作表、每表 100,000 行、总计 1,000,000 个有效单元格；
- 达到任何预算即失败并记录结构化错误，不产生部分或伪造结果；
- 不执行宏、外链、公式或 HTML；公式只按不可执行文本/缓存值处理；
- 解析异常不影响上一次可用索引；日志不记录单元格正文和本地私人路径；
- MVP 不通过 HTTP、消息连接器或 Runtime Tool 暴露通用 XLSX 解析。

工作表/行/单元格限制将在实现时以回归测试固定；若库无法可靠施加这些预算，则按 X5 禁用旧版 XLSX 支持，不以“升级版本”代替隔离控制。

## 3. 备选方案比较

| 方案 | 功能保留 | 安全/审计 | 可复现性 | 结论 |
|---|---|---|---|---|
| A. 官方 0.20.3 tarball 本地固定 | 保留 | 有机会清除已公告问题，仍需边界测试 | 高 | **推荐** |
| B. 删除依赖并禁用旧版 XLSX | 不保留该旧入口 | 最小攻击面 | 高 | 可靠回退方案 |
| C. 继续使用 0.18.5 | 保留 | high 告警持续存在 | 中 | 不允许进入发布基线 |
| D. 使用其他解析库 | 需重新验证兼容 | 新依赖面和迁移风险 | 取决于库 | 当前没有足够收益，不推荐 |

## 4. 确认后的验收证据

- tarball 来源、SHA-256、许可证与包清单记录；
- lock 中只引用本地固定制品；
- 正常 XLSX、损坏文件、超大文件、工作表/行/单元格超限测试；
- 路径逃逸、符号链接/联接点、重复索引和失败恢复测试；
- Node `24.19.0` 下完整测试、构建和隐私扫描通过；
- `npm audit --omit=dev` 不再报告当前 SheetJS 告警；
- 能力矩阵继续标明这是“旧版受控读取”，而不是通用上传/生产导入服务。
