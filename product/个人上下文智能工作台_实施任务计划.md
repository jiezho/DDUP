> 版本：V2.3
> 日期：2026-08-27
> 状态：执行基线  
> 适用范围：从已完成的产品原型进入 MVP 工程化、试运行与发布  
> 执行方式：人负责目标、取舍、授权与验收；Codex 负责分析、实现、验证和文档同步

## 0. 计划结论

项目不从零开始。需求分析、UI/功能 Spec、高保真原型、竞品调研和 Runtime 评估已经完成；G1–G5b 已通过，核心项目闭环、权限优先全文检索和受保护混合检索实验切片已经落地。独立合成盲测、阈值校准和精确 chunk locator 已完成；sidecar 持续调用退化已通过缓存与有界背压完成短样本修复，但扩展边界 Top-1 仍未通过，正式默认仍为 FTS，当前转入长文错排与英文长尾质量分析。

后续按九个阶段推进：

1. 工程治理与现状基线；
2. MVP 范围冻结；
3. 架构、数据和权限冻结；
4. 基础平台与项目垂直闭环；
5. 个人上下文知识库与引用问答；
6. Agent Runtime 与 AI 治理；
7. 专业工作台与学习提升；
8. 移动端与飞书连接器；
9. 试运行、评测与发布。

首个可交付版本只证明一个核心闭环：

> 建立项目 → 汇聚文档和知识 → 讨论并形成决策 → 跨来源检索和带引用问答 → 形成任务 → 今日执行 → 日终复盘。

科研、AI 应用探索、前沿跟踪、学习提升等首期以“项目模板 + 专业对象/视图”扩展，不分别建设独立的数据底座。

## 2. 执行与确认规则

### 2.1 任务状态

| 状态 | 含义 |
|---|---|
| `待开始` | 前置条件未满足或尚未排期 |
| `进行中` | Codex 正在生成、实现或验证 |
| `待确认` | 文档或演示已完成，需要用户作出产品/架构/授权决定 |
| `已确认` | 用户已明确接受或给出修改意见并完成修订 |
| `已完成` | 交付物、测试和文档均达到验收条件 |
| `已阻塞` | 存在无法在当前权限或上下文内解决的外部阻塞 |

### 2.2 Codex 可直接执行

- 读取、整理和交叉检查现有代码与文档；
- 在既定范围内创建或更新代码、测试和文档；
- 使用虚构演示数据完成开发和测试；
- 运行非破坏性的构建、测试、隐私扫描和页面验证；
- 修复不改变产品含义的缺陷、文档不一致和低风险工程问题；
- 输出差异、风险、截图、测试结果和后续建议。

### 2.3 必须由用户确认

- MVP 范围、优先级和明确非目标；
- 会改变使用模式的信息架构或关键交互；
- 技术栈、存储、部署、身份和公司数据边界；
- 新增生产依赖、外部云服务或可能持续产生费用的服务；
- 接入真实个人/公司资料、账号、密钥或第三方平台；
- 外部写入、发送消息、发布、删除、权限变更和不可逆迁移；
- Harness/Hermes 的正式纳入、发布范围和上线决定。

### 2.4 文档确认方式

需要确认的文档统一采用文件名后缀 `_待确认`，文首列出“需要确认的决定”和 Codex 推荐默认项。用户可以：

1. 全部同意；
2. 按编号修改某几项；
3. 要求补充备选方案或验证；
4. 暂缓某项并采用文档中的保守默认值继续不受影响的任务。

确认后移除文件名中的 `_待确认`，在文首记录确认日期和决定，并把关键技术选择写入 `product/ADR/`。

## 6. 任务交付完成定义

一个任务只有同时满足以下条件才标记为“已完成”：

1. 需求或问题有明确来源和范围；
2. 代码/文档变更与既有决策一致；
3. 对应测试、构建或人工验证已执行；
4. 演示数据明确为虚构，不含真实个人或公司信息；
5. 错误、空态、权限态和回退路径被考虑；
6. 变更影响、风险和未完成事项已记录；
7. 需要用户确认时已有明确确认记录；
8. 相关需求、Spec、API、测试和运行手册已同步。
9. 每次代码更新交付时已启动或验证本地回环试运行，并给出实际访问地址。
